# Video, capture, and latency

Investigation date: 14 October 2026. Static Windows-binary analysis on Linux; no live camera, DLL execution, gate operation, or physical latency measurement. Addresses are preferred virtual addresses (ASLR may relocate them). QY means `VideoDrivers/IPC_QY/IPC_QY.dll`, not the different QY1 copy.

QY calls Net_StartVideo at 0x10005bd9 and Net_StopVideo at 0x10005c47. The header defines StartVideo(handle, streamType, HWND), so this path is SDK-managed playback into a Windows window. Net_ImageSnap at 0x10005cc8 is a separate snapshot operation. Its header says image information is delivered through the registered capture callback. Calling a snapshot is not a continuous video strategy.

CamAPI.h exposes CAM_StartStream separately from CAM_SetCaptureCallback/CAM_Capture. QY's native image callback 0x10006c80 forwards metadata and picture pointers to 0x10006d40; it does not obtain plate text by scraping displayed video.

Ghidra separates that recognition callback from display video. QY1 `FUN_10005c00` at 0x10005c00 calls `Net_StartVideo(handle, 0, window)`. `Net_StartVideo` in QY NetSDK (0x1001ed00, version string `SDK_3.2.2.5 build-1710231600`) calls `Play_OpenCamera` and does not read the plate callback. `Play_OpenCamera` at 0x10002240 opens a decoder port, calls `Decode_StreamOpenEx` with a 0xFA000-byte buffer, starts decode, calls `Rtsp_StartVideo(camera, streamType, 1)`, and starts a receive thread plus a signal thread. `Rtsp_StartVideo` at 0x100050f0 builds the URL in `FUN_10003c60`, then allocates a 10-slot ring whose slot size is 0xC8000 and a task. The module contains the formats `RTSP://%s:%d/video` and `RTSP://%s:%d/subvideo`. Other format strings include account material and were redacted. Which stream type selects which path is inside `FUN_10003c60` and was not decompiled. `FUN_10003510` closes and reopens a camera, so this player has a restart path. `Play_GetFrameData` and `Play_GetJpgBuffer` forward to DecodeSdk; they are not the recognition callback.

Park.exe, after a successful `DV_OpenDevice` at 0x49ae55, calls `DV_StartStream(handle, 2, window)` at 0x49af08 and `DV_SetCaptureCallback` at 0x49af31. The QY1 adapter does not forward that stream-type argument 2; it passes 0 to `Net_StartVideo`. Measured glass-to-glass latency and whether the decoder drops old frames are still unresolved. The bundled libraries are on this path, which is stronger than their presence in the folder.

SmartPark already implements bounded latest-frame buffers (`app/services/latest_frame.py`), a one-notification GUI mailbox (`app/desktop/frame_mailbox.py`), a persistent local MediaMTX decoder (`app/services/recognition_decoder.py`), and asynchronous OCR dispatch (`app/recognition_worker.py`). The decoder reads only local port 8554, selects the newest complete JPEG in accumulated bytes, and times out when no complete frame arrives. These protections do not measure delay already accumulated at the camera or upstream decoder.

Critical measurement distinction: FrameSample.received_at is assigned at buffer insertion. A freshly received old camera frame can have low local age. Host receive-age alone cannot certify low glass-to-glass latency. Preserve camera timestamp/PTS where available and use a filmed clock or LED test at the scene to establish actual delay.

Acceptance proposal, not measured performance: target live p95 <=500 ms on the site LAN, recognition p95 <=1 s from a readable plate, recovery <=10 s after a brief disconnect, with no increasing delay over a 30-minute run. Record actual distributions before accepting or revising targets. Test both lanes, empty lanes, stationary vehicles, slow OCR and UI open/closed. Separate native event delay, decoder delay, OCR duration and display delay. Tune bitrate/GOP/FPS only after measuring; lower resolution can reduce OCR accuracy.
