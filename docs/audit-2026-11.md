# Zirp production audit — 20 November 2026

Scope: Site Service (FastAPI), Recognition Worker, media gateway / HVX host
client, PostgreSQL layer, payments (ClickPesa only), barrier control, manual-open
alerts, Windows installer and recovery. Branch `production-readiness`, working
tree as found (many uncommitted changes from the user and earlier sessions were
left untouched). Nothing was committed.

Status key: **verified** (code read and proven by a test or measurement),
**fixed** (defect found, fixed, regression test added), **needs hardware**
(cannot be proven without real cameras / barriers / provider), **open risk**
(known gap, not fixed here).

How tests were run: the repo `.venv` is Linux-only, so tests ran on the
embedded runtime `build\installer\stage\python64\python.exe` with pytest on
`sys.path` (runner script puts the repo first; see "Test harness findings").
PostgreSQL-only tests ran against a **throwaway PostgreSQL 18 cluster** created
with `initdb` in a temp folder on port 55432 (user `audit`, trust auth,
127.0.0.1 only). The live `smartpark` database on 192.168.1.240:5432 was never
written to, and no live service was stopped or reconfigured.

| F3 | Barrier / DB | `_apply_answer` (gate command result) was read-modify-write: two answers racing on separate connections could let a late FAILED overwrite an ACCEPTED. | Conditional `UPDATE … WHERE ok IS FALSE` for failure answers. `app/services/decisions.py` | `test_pg_racing_gate_answers_keep_one_command_row` (PostgreSQL, 8 threads; also repeated 15× before the fix without a hit — the window is small but real) |

## Test harness findings

- `python -m app.<module>` with the embedded runtime imports
  `build\installer\stage\app` (the **staged copy**), not the repo, because the
  `._pth` file ignores the working directory. Run repo code through a wrapper
  that inserts `C:\SmartParkEdge` first (as the pytest runner does).
- The pytest runner must guard `pytest.main()` with `if __name__ == "__main__":`
  or multiprocessing tests (spawn) re-run the whole suite and fail.
- Tests read the PC's live `%ProgramData%\SmartParkEdge\config\zirp.env` unless
  `SMARTPARK_ENV_FILE` points elsewhere; three ClickPesa tests then see the
  site's MOCK mode. The conftest should pin an empty env file.

## Follow-ups

Done since the audit (20 November 2026):

- The Tanzania profile is set on the live server (`SMARTPARK_ALPR_COUNTRY=tanzania`
  in `zirp.env`). It takes effect at the next service restart, which installing
  1.0.0-rc4 does.
- The installer was rebuilt as **1.0.0-rc4** from a clean commit, with all the
  fixes above and a new Update / Repair page in the setup wizard.
- The technician-docs test now checks the current guides in `docs/`.

Recognition follow-up (1.0.0-rc5), from 30 hours of live data:

- **Best read wins per car**: a held weak read (79% of 704 px live-stream reads
  were held, average confidence 0.67) no longer swallows the camera's better
  snapshot of the same car. Before, exits went undecided and 27 entries took
  the weak read's plate. Two agreeing frames also release a hold.
  `tests/test_visit_best_read.py`.
- **TZ validation** accepted any read starting with `T` (`TQYOTA`, `T70DMT`);
  it now accepts real Tanzanian formats only and holds the rest for an
  operator.
- **Event-loop stalls** (726 in 31 h): display cropping of every camera still
  moved off the main loop.
- **Edge Node calibration**: the node's account now gets a Camera calibration
  page; the Site Server names the node that runs a camera.
- Start/end lines can't change when the camera's own trigger fires; use
  `SMARTPARK_CAPTURE_TRIGGER=zirp` to let the start line trigger the read.

Camera mix-up and display follow-up (1.0.0-rc6):

- **One lane's reads filed under the other lane.** The camera SDK host numbers
  its sessions 0, 1, ... in connect order and renumbers them after a restart.
  Video sessions and the event poller kept the number stored in the shared
  database, so 2# Exit read 2# Entry's session: byte-identical photos were
  saved as both cameras 21 ms apart (2#: 38 pairs in 24 h). Every camera now
  finds its session by IP on the live host; a changed session restarts the
  video cleanly. `tests/test_camera_handle_mixup.py`.
- **Good plate replaced on screen by a later misread** of the same car
  (T760DCB -> T260DCB). Sessions were already safe (DUPLICATE); the display now
  keeps the better plate for 10 s unless a clearly different car arrives.

Shadow mode, lane fallbacks and SDK session churn (1.0.0-rc7):

- No visit had closed since 29 Oct: with developer gate opening off, every
  exit ended GATE_UNAVAILABLE. Authorized exits are now recorded and closed
  in that mode (`tests/test_authorization_commit.py`, shadow-mode tests).
- rc6 regression: a changed SDK session number counted as a failure, and the
  restore loop re-logged into connected cameras; reconnects rose to 538 an
  hour. Both fixed (`tests/test_camera_handle_mixup.py`).
- Live Gates fallbacks: Ticket (F6) at entry, Scan (F7) at exit
  (`tests/test_entry_fallback.py`).
- The test suite no longer writes secrets into the site's ProgramData folder.

Still open:

1. Label the `TestingData` stills (at least 100, day and night) so false
   positives and negatives become a regression gate.
2. Two-row plates under headlight glare are still the main cause of missed
   reads. Camera exposure or IR settings will help more than OCR changes.
3. On site: multi-camera soak, camera cable pull and HVX host restart, barrier
   relay failure, a real power cut, a reboot, a clean install, and a live
   ClickPesa payment.
